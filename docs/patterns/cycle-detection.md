# 快慢指標與循環偵測

[回學習索引](../readme.md) · [測試方法](../testing.md)

當每個狀態只有一個後繼狀態，且路徑最後落在有限集合內，就必定形成循環。Floyd 方法讓慢指標每輪走一步、快指標走兩步，在循環中藉由速度差相遇，不必保存走過的狀態。[#141](linked-list.md) 用它找串列環，#202 則用它處理數值轉換。

## 202 · Happy Number

[解法](../../src/math/lc_202_happy_number.py) · [測試](../../tests/math/test_lc_202_happy_number.py) · 難度：Easy · Group：`math`

給定正整數 n，反覆將它替換成十進位各位數字的平方和；能到達 1 就回傳 `True`，否則回傳 `False`。題目輸入範圍為 `1 <= n <= 2^31 - 1`。目前測試未涵蓋零、負數或非整數，這些不屬於題目輸入前提。

### 推理與解法步驟

令 f(n) 為數位平方和。若 n 有 d 位，則 `f(n) <= 81d`；大數經過轉換會縮小，最後進入有限狀態內。轉換規則固定，一旦狀態重複，之後就會沿同一循環前進。

1 是固定點，因為 f(1) = 1。若路徑到達 1，兩指標最後都會停在 1；若進入其他循環，兩者也會相遇，但相遇值不會是 1。因此相遇後只要檢查 `slow == 1`，不必找循環入口。

1. `sum_of_squares` 用 `% 10` 取個位數、累加平方，再用 `//= 10` 移除個位數，直到數字用完。
2. 將 `slow`、`fast` 都設成 n。
3. 每輪先讓 slow 轉換一次、fast 轉換兩次，再檢查相等。必須先移動，否則起始值相同會直接結束。
4. 相遇後跳出迴圈，回傳 `slow == 1`。

```text
19 → 82 → 68 → 100 → 1 → 1
輪次    slow    fast
起始    19      19
1       82      68
2       68      1
3       100     1
4       1       1     相遇，回傳 True

2 → 4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4 → …
兩指標最後在非 1 循環內相遇，回傳 False。
```

### 複雜度

以整數運算為 O(1) 的模型分析，首次處理 d 位數需要 O(d) 時間；後續狀態位數迅速縮小，最後進入固定大小的循環，總時間為 O(d)，亦即 O(log n)（n = 1 仍需常數時間）。只保存兩個狀態與數位累加值，額外空間為 O(1)，沒有字串、切片、集合或遞迴。空間以整數變數數量計算，未計入任意精度整數的位元成本；題目範圍內整數大小有固定上限。

### 集合版參考解法

source 另有 `is_happy_oracle`，供測試交叉驗證。它以 `seen` 記錄已處理狀態：只要 n 不是 1 且尚未出現，就先存入集合，再計算下一個數位平方和。到達 1 時回傳 `True`，遇到重複狀態時回傳 `False`。與 Floyd 相比，它直接記錄歷史狀態，較容易追蹤停止原因。

令 k 為停止前處理的不同狀態數，d 為輸入位數。在集合查找與新增平均為 O(1) 的模型下，時間可保守表示為 O(kd)，額外空間為 O(k)，不能套用 Floyd 的 O(1) 空間結論。程式目前標註回傳型別為 `int`，但實際回傳 `n == 1` 的布林結果。

### 現有測試與邊界

10 組參數化案例以 `actual is expected` 檢查布林回傳值：

| 輸入 | 預期 | 檢查重點 |
| --- | --- | --- |
| 19、2 | True、False | 題目正反例 |
| 1 | True | 起點已是固定點 |
| 7 | True | 多步後到達 1 |
| 10、100 | True | 含零數字，轉換後到達 1 |
| 4、20 | False | 非 1 循環中的不同起點 |
| 82 | True | 從 19 路徑的中間狀態開始 |
| 999 | False | 多位數的不快樂數 |

```bash
poetry run pytest tests/math/test_lc_202_happy_number.py -q
```

另外，`test_is_happy_property` 使用 `@given` 與 `st.integers(min_value=1, max_value=2**31 - 1)` 生成合法正整數，將 `isHappy(n)` 與 `is_happy_oracle(n)` 的結果用 `==` 比較。這是在相同輸入下用不同循環偵測方式交叉驗證，不是窮舉整個範圍，也不保證每次都生成上界。

兩個版本都用取餘數與整除計算數位平方和，可能共享同類錯誤，因此保留人工可驗算的 10 組固定案例。固定案例檢查布林身分，生成測試則只比較結果相等；目前沒有效能量測。

延伸建議：加入 `2**31 - 1` 的固定案例，讓上界每次都會被測到。
